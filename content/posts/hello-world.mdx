Welcome to the new `nurul.dev` (or `nurul.com.bd` — same site, canonical lives at the latter). The old portfolio served me well for a couple of years, but it accumulated the usual rot: deps drifted, the build chain creaked, and I'd long since stopped writing into it. So I rebuilt it from scratch.

## The brief I gave myself

A portfolio for an engineer should look like the things the engineer uses. Mine looks like a terminal because that's where I spend most of my day — `ssh`'d into VPS boxes, reading `journalctl`, tailing nginx logs.

- **No CMS.** Content is TypeScript files and MDX. I edit in the same editor I write code in.
- **No Vercel.** I host my own infra. This deploys to an Ubuntu box behind nginx, `next start` under systemd.
- **No giant gradient hero.** Plain `whoami`, prompt headers, `git log` for experience, `tree` for skills.

## The stack

```ts
// Decisions I'm locking in
const stack = {
  framework: "Next.js 15 (App Router)",
  runtime: "React 19 + TypeScript strict",
  styling: "Tailwind v3.4",
  motion: "Framer Motion",
  content: "MDX via next-mdx-remote",
  email: "Resend",
  deploy: "Ubuntu + nginx + systemd",
};
```

A few notes on the picks:

1. **App Router over Pages.** Server Components are a real win for a content-heavy site like this — almost everything ships as zero JS.
2. **Framer Motion over GSAP.** Tree-shakable, smaller bundle, fine for the motion this site actually does.
3. **`next-mdx-remote` over `@next/mdx`.** Posts as files, no MDX-as-routes compile step. Easier to scale to hundreds of posts later.
